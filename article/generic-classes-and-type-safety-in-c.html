Generic Classes and Type Safety in C

This article explores generic classes in C#, explaining what they are, how they work, and the critical role they play in modern software development. You will learn how generics replace non-generic collections, eliminate runtime casting errors, and enforce strict compile-time type checking to improve code reliability, readability, and performance.

What Are Generic Classes in C#?

A generic class is a blueprint that defines a class with placeholders, known as type parameters, for the data types it stores or manipulates. Instead of committing to a specific data type like int, string, or object during class definition, you specify the type parameter using angle brackets (commonly <T>).

When an instance of the generic class is created, the developer specifies the actual data type to substitute for T.

public class Storage<T>
{
    private T _data;

    public void SetData(T data)
    {
        _data = data;
    }

    public T GetData()
    {
        return _data;
    }
}

In this example, Storage<T> can be instantiated as Storage<int>, Storage<string>, or any custom class without rewriting the underlying logic.

How Generic Classes Improve Type Safety

Before generics were introduced in C# 2.0, developers relied on generalized classes like ArrayList that stored elements as the base System.Object type. While this allowed collections to hold any data type, it severely compromised type safety. Generics resolve these issues through three primary mechanisms:

1. Enforcing Compile-Time Type Checking

When using System.Object, a collection can accept any data type, which often leads to errors that are only discovered at runtime:

// Non-generic approach
ArrayList list = new ArrayList();
list.Add(42);
list.Add("Hello"); // Compiles fine, but introduces mixed types

int number = (int)list[1]; // Throws InvalidCastException at runtime

Generic classes prevent this scenario entirely. The C# compiler enforces that only elements matching the declared type parameter can be passed into the class:

// Generic approach
List<int> list = new List<int>();
list.Add(42);
// list.Add("Hello"); // Compiler Error: Argument cannot convert from 'string' to 'int'

By shifting type validation from runtime to compile time, generic classes catch mistakes during the build phase, preventing unexpected crashes in production.

2. Eliminating Explicit Type Casting

Because non-generic collections store objects, every retrieved item requires explicit casting back to its original type. Explicit casts introduce human error and make the codebase brittle to refactoring.

With generic classes, the compiler already knows the return type. When you invoke GetData() on a Storage<string>, the compiler guarantees that the return value is a string, removing the need for manual type casting and reducing boilerplate code.

3. Preventing Boxing and Unboxing Overhead

Type safety directly affects application performance when dealing with value types (such as int, double, or custom struct types). Storing a value type inside a non-generic object container triggers "boxing," which wraps the value type into a reference object allocated on the managed heap. Extracting the value triggers "unboxing," requiring an explicit cast.

Generic classes instantiate specialized versions of the code for each value type at runtime via the Common Language Runtime (CLR). A List<int> stores integers directly in a contiguous block of memory, avoiding the performance and memory penalties of boxing while maintaining strict type boundaries.

Constraining Generic Types

To ensure even greater type safety, C# allows you to apply generic constraints using the where keyword. Constraints restrict the types of arguments a client can use when instantiating a generic class:

public class Repository<T> where T : class, new()
{
    public T CreateDefault()
    {
        return new T(); // Safe because of the 'new()' constraint
    }
}

Constraints allow you to specify that T must be a reference type (class), a value type (struct), implement a specific interface, or inherit from a particular base class. This gives your generic class safe access to specific methods and properties on T without relying on casting or reflection.
