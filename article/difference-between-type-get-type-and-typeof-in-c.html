Difference Between Type.GetType and typeof in C

In C#, both typeof and Type.GetType are used to obtain a System.Type object that represents a specific data type, but they operate at fundamentally different stages of program execution. The typeof operator is evaluated at compile time and requires a compile-time type identifier, while Type.GetType is a static method evaluated at runtime that resolves a type from a string name. Understanding the differences between these two approaches is essential for writing efficient, type-safe, and dynamically extensible .NET applications.

1. Compile-Time vs. Runtime Resolution

  • typeof (Compile-Time): The typeof keyword is an operator built directly into the C# language. It takes a type name directly (not an instance or a string) and resolves the Type metadata at compile time. Because the compiler validates the type, any misspelling or missing reference results in an immediate build error.
  • Type.GetType (Runtime): Type.GetType is a method provided by the System.Type class in the .NET Base Class Library. It accepts a string parameter and searches for the corresponding type dynamically during execution. If the string is malformed or the type does not exist, the failure only surfaces while the application is running.
// Compile-time resolution
Type compileTimeType = typeof(System.String);

// Runtime resolution
Type runtimeType = Type.GetType("System.String");

2. Input Requirements and Flexibility

  • typeof: Requires the type to be referenced by the project at compile time. You cannot pass a variable, a string, or an expression to typeof.
  • Type.GetType: Accepts strings, enabling dynamic behaviors such as reading type names from configuration files, user input, or external databases. It also accepts Assembly Qualified Names (AQN), allowing it to locate types in assemblies that were not referenced when the application was compiled.
// Type.GetType using an Assembly Qualified Name
string typeName = "MyNamespace.PluginClass, MyPluginAssembly, Version=1.0.0.0, Culture=neutral, PublicKeyToken=null";
Type dynamicType = Type.GetType(typeName);

3. Performance Differences

  • typeof: Highly optimized. The compiler emits a ldtoken (load token) Intermediate Language (IL) instruction followed by a call to Type.GetTypeFromHandle. The CLR handles this with minimal overhead, making typeof virtually instantaneous.
  • Type.GetType: Considerably slower. It requires parsing the input string, scanning loaded assemblies, and potentially loading new assemblies from disk via reflection. While results may be cached internally by the CLR, the overhead remains substantially higher than using typeof.

4. Error Handling and Nullability

  • typeof: Safe against null and missing types at runtime. Because it is checked by the compiler, typeof(T) will never return null.
  • Type.GetType: By default, if the specified type cannot be found, Type.GetType returns null instead of throwing an exception. However, it provides overloads that allow you to control this behavior:
// Returns null if not found
Type t1 = Type.GetType("NonExistentNamespace.FakeType");

// Throws a TypeLoadException if not found, with case-sensitivity set to false
Type t2 = Type.GetType("system.string", throwOnError: true, ignoreCase: true);

Summary: When to Use Which

Feature typeof Type.GetType
Execution Point Compile time Runtime
Input Type identifier (e.g., int, MyClass) String name (e.g., "System.Int32")
Type Safety High (checked at compile time) Low (can fail or return null at runtime)
Assembly Dependency Must be referenced at compile time Can be dynamically resolved at runtime
Performance Extremely fast Slower due to reflection and string parsing

Use typeof whenever you know the target type during development, as it guarantees type safety and maximum performance. Reserve Type.GetType for dynamic scenarios such as plugin architectures, dependency injection containers, and serialization systems where type names are supplied as text at runtime.
